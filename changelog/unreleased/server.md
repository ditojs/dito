### Behaviour changes

- **server:** Dito.js 7 replaces the Koa and Objection.js server: `Application`, `Model`, `QueryBuilder`, `Validator`, the controller classes, services, storages, the CLI and logging are removed. See [Upgrading to 7.x](docs/upgrading-to-7.x.md) for each change, and for the steps to move an app.
- **server:** `@ditojs/server` is a core on [Hono](https://hono.dev). `createApi({ controllers, middleware, adapter, getUser, onError })` returns a Hono app, which the app routes with `app.route('/api', api)`. There is no configuration. An API handles only the paths of its actions, so apps add `app.notFound(notFound)` and `app.onError(createErrorHandler())` for Dito's JSON errors.
- **server:** Controllers are plain objects from `defineController()`, with one `actions` map keyed `'verb path'`. A path that starts with `:id` is a record action, and paths use Hono's syntax. `true` routes a default handler, a function replaces the handler beneath it and runs it as `next()`, and an object without `handler` adds settings. Default handlers are off unless a layer sets them.
- **server:** Every callback gets one object, its context. Handlers get `handler(context)`, with `query`, `body`, `params`, `user`, `em`, `action`, the app's own Hono variables, Hono's context `c` and `next()`. Middleware is Hono middleware, `(c, next)`, and reads the same values from `c.var`. The other callbacks get `c` and their values by name, such as `authorize({ c, user })`, `getUser({ c })` and `onError({ error, c })`. Apps type their own variables by augmenting `DitoVariables`.
- **server:** Handlers return data or a `Response`. Data responds with 200 and `undefined` with 204, unless the handler sets another status with `c.status()`. Hono doesn't send a thrown `Response`: throw an `HttpError`, or return the `Response`.
- **server:** Mixins from `defineMixin()` replace features, base classes and hooks.
- **server:** `authorize` takes `true`, a role, a list of roles, or a function that gets `{ c, user }` and grants access by returning `true`. If a write action has no `authorize`, on itself or on a layer, `createApi()` throws. `isAuthorized(c, authorize)` checks it, also in `createAdmin()`.
- **server:** `HttpError` replaces `ResponseError` and its subclasses: `new HttpError(status, { message, type, code, errors })`. The error JSON stays `{ type, message, status, code, errors }`. Field errors are keyed by path, such as `chapters/8/title`, each with a `message` and a `keyword`. `createValidationError(issues, options)` builds a 400 from Zod issues.
- **admin:** Requests reject with an `ApiError`, which has the fields of the JSON body, the `status` and the `response`. Code that read `error.response.data` reads the fields on the error. See [Upgrading to 7.x](docs/upgrading-to-7.x.md#10-update-the-admin-the-clients-and-the-tests).
- **admin:** The `api` config is plain data. `request`, `getApiUrl`, `isApiUrl`, `normalizePath`, `denormalizePath` and `resources` aren't options any more, and `admin.api` has `request()` and `getApiUrl()`. `normalizePaths` is gone: views and sources are routed under their hyphenated names. `users` takes only `path`, and the admin loads its user from `get self`.
- **schema:** `@ditojs/schema` is removed. The admin holds the validators that it uses.
- **router:** `@ditojs/router` is removed. Hono routes the actions.
- **build:** `@ditojs/build` isn't published any more. `defineAdminViteConfig()` uses `autoprefixer`, an optional peer, instead.
- **admin:** Sources in forms show the permission error for 403 responses, as they do for 401 responses.
- **admin:** Resource paths are joined without a trailing slash when a resource's path is empty.
- **admin:** List scopes set list filters with `filter`, and the order with `order`: `{ label, hint, filter, order, defaultScope }`. The admin sends them as `filter=name:args` and `order`, and keeps `?scope=` in its own URL only.

### New

- **server:** Schemas of actions, filters and column types are Zod schemas. `defineAction({ query, body, handler })` types `query` and `body` of the handler's context. Dito converts the strings of query values and filter arguments to the numbers, booleans, dates and arrays that their schemas expect, through the schemas' JSON Schema. A repeated key of a single value responds with 400. Unions, transforms and other types get the strings.
- **server:** `c.var.body` holds the body of a write, parsed once, for middleware and the handler. `sendFile(c, body, { filename, type, inline })` responds with a file, also a stream.
- **server:** `hostMiddleware()` returns Hono's `secureHeaders()`, `csrf()` for requests with `Origin`, and `bodyLimit()`, and optionally `cors()` and `etag()`.
- **server:** `@ditojs/server/node` has `serve()`, a Node server that stops on signals, `forwarded(proxy)` for apps behind reverse proxies, and `getClientAddress(c)`.
- **mikro:** `defineModelController()` of `@ditojs/mikro` builds model controllers on MikroORM 7 entities, with `find`, `filters`, `defineFilter()`, `defineTextFilter()` and `defineDateRangeFilter()`. A filter that the URL repeats, such as a scope's and the panel's, narrows the list by both, as in Dito.js 6. Writes check the JSON types of values, the lengths of strings, empty required strings, the integer digits of decimals, the ids of relations and the schemas of custom types. Postgres checks the rest, and a `body` schema on the action adds stricter rules.
- **mikro:** A one-to-many relation to a pivot entity with `orphanRemoval` writes the pivot rows with their columns, such as `{ bookLinks: [{ book: 12, dueDate }] }`. A pivot row is keyed by its relation that isn't the one back to the parent. A body that also writes the many-to-many relation of the same pivot entity responds with 400. Two owned rows with the same key respond with 400.
- **mikro:** `fields` alone defines what goes out. Dotted paths populate their relations, and a relation to one row goes out as `{ id }`. Writes take `{ relation: { id } }`, and `order` and filters name `relation.id`. Serialization `groups` aren't supported.
- **mikro:** Handlers get the controller's `entity`, `getRecord()`, `find()`, `list()` and `getListQuery()`, also as `c.var.getRecord()` and so on. A `load` option replaces how `getRecord()` loads, `maxRows` of a find limits its lists, and the `crud` mixin routes the five default handlers.
- **mikro:** `serialize({ record, json, c })`, `beforeSerialize({ records, c })` and `deserialize({ json, record, c })` shape the records of a controller. Filters get `where({ value, name, c, em })`, and `find` and `load` as functions `({ c, user })` and `({ c, id })`.
- **mikro:** The package also has `setRecord()`, `createRecord()`, `assignRecord()`, `defineJsonType()`, `createEntityUserSource()`, and `createMikroAdapter()`, the `adapter` of `createApi()`.
- **mikro:** Handlers get the request's entity manager as `em` of their context, and middleware as `c.var.em`. `import '@ditojs/mikro/types'` types it as MikroORM's `EntityManager`.
- **mikro:** `createMikroAdapter(orm)` also has `getKysely()`, a Kysely on the ORM's pool outside of any transaction, for sessions, credentials and jobs.
- **storage:** `@ditojs/storage` has the disk and S3 storages, `createStorages()`, and `createAssets()`, which binds the adapter, paths and storages of an app, with the mixins `defineWrites(table)` and `defineUploads(table, { uploads })`, and `store()`, `import()`, `findReferences()` and `runJobs({ deleteUnusedAfter })`. With the request's `c`, `findReferences()` reads in the request's transaction. `serveStorage()` of `@ditojs/storage/node` serves disk storages.
- **storage:** A write accepts a file when its key has an `asset` row in the storage of its path, and imports other files from their `url` when the storage allows it. File objects have no signatures. `assets.runJobs()` tracks files by scanning the data, so the `asset` table has no `count`. An app runs the scan once at the release.
- **auth:** `@ditojs/auth` has sessions as Hono middleware from `createSessions()`, and `defineUserActions()`, a mixin with the actions of the admin's users, with passkeys, TOTP and password reset. Its `get features` tells the admin what to offer, so `createAdmin()` takes no features. Apps describe their users in a user source, such as the one of `createEntityUserSource()`, whose entity hides `hash`. `definePasswordWrites()` is a mixin that hashes the passwords of a model controller, and asks for confirmed access when users change their own password or username.
- **auth:** `createSessions()` and `createCredentials()` take the API's `adapter`, and use its `getKysely()` outside of the requests' transactions. The sessions have `deleteExpired()` and `readSignedCookie(c, name)`, and the credentials `deleteUsers(source, ids, { c })`, which runs in the request's transaction with `c`.
- **auth:** The `session` and `credential` tables stay. Sessions sign their cookie with Hono's signed cookies, so existing sessions end once and users log in again.
- **auth:** The body of `post login` and `post password-reset` names the user as `username`. Logins respond with `{ user }` or `{ codeRequired: true }`, and `get self` replaces `get session`. New passwords need at least 8 characters by default, and the `password` schema of the user source changes it, such as `createEntityUserSource(Admin, { password })`.
- **admin:** `createAdmin()` of `@ditojs/admin/server` serves the admin as a Hono app, with Vite in development and the build of `dist` otherwise. `authorize` protects the views, which the build puts below `views/`. `defineAdminViteConfig()` from `@ditojs/admin/vite` builds the admin on Vite 8, whose options are `build.rolldownOptions`.
- **server:** `createApi()`, `createAssets()` and `createAdmin()` check their configuration at startup: roles in `authorize` without `getUser`, `transacted: true` without the adapter's `transaction`, unknown storages, and a missing `dist`.
- **mikro:** `defineMikroConfig()` makes `p.date()` columns keep the local day, fills the defaults of `defineJsonType()` schemas in new rows, and warns of pivot entities with an id of their own. The `assets` of `defineJsonType()` and `getAssetPaths()` declare asset paths on the entities.
